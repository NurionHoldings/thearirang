# 아리랑마켓 지역 주문·자체 라이더 운영

진입: `/arirang-market.html` → `/arirang-local.html`.

## 지역과 입점업체

운영자가 소도시는 `city`, 대도시는 `district` 또는 `dong`으로 지역을 등록한다. 같은 시의 구/동 배송 구역을 함께 등록할 수 있으며 더 구체적인 지역을 우선 선택한다. 구가 없는 세종시는 시 단위로 설정했다. 대전 동구·홍도동과 세종시 지역만 초기 등록하며 가상 업체·상품·재고는 만들지 않는다.

시 단위 IP 위치는 처음 접속 시 자동으로 확인한다. IP만으로 구/동을 추측하지 않는다. 사용자가 내 위치로 연결을 누르면 브라우저 위치 동의와 Kakao 행정/법정 구역 조회를 통해 연결한다. 이미 위치 권한이 허용된 기기는 자동 정밀 연결도 시도한다. 직접 선택한 지역은 이 브라우저에 보존한다. 등록되지 않은 지역은 다른 지역으로 강제 연결하지 않는다.

업체에는 소재 지역과 실제 배송 가능 지역, 배송비, 최소 주문금액, 승인·영업 상태를 별도 저장한다. 상품은 업체에 귀속되며 다른 업체 상품을 같은 주문으로 접수할 수 없다. 기본 업체 정원 100개, 업체별 상품 50개이며 SQL 잠금으로 한도를 검사한다.

## 주문과 배송

1. 구매자는 지역 → 업체 → 상품 선택 → 업체별 장바구니 → 배송주소 확인 → 현장결제 주문 접수 순서로 이용한다.
2. 구매자 세션은 HttpOnly 쿠키로 발급된다. 이름·전화·주소는 장바구니 localStorage에 넣지 않는다. 주문 조회는 같은 브라우저의 24시간 세션에 한정된다. 장기 주문조회·다른 기기 복구에는 추후 고객 인증 연동이 필요하다.
3. 가격·배송비·재고·영업·배송 구역을 서버에서 다시 검사하고 DB 트랜잭션으로 판매가능 재고를 차감한다. 같은 주문 키 재전송은 같은 주문을 반환하며 내용이 바뀌면 거부한다.
4. 판매자는 접수 → 준비 → 픽업 준비 완료로 진행한다. 접수 전 고객 취소, 판매자 거절, 준비 중 업체/운영자 취소는 재고를 한 번만 반환한다.
5. 근무 중이며 해당 배송 구역에 등록된 라이더만 수락한다. 운영자 수동 배차·사유 기록 후 재배차도 지원한다. 한 라이더는 한 번에 한 주문을 담당한다. 동시 수락은 주문 및 라이더 행 잠금과 버전 검사로 충돌을 막는다.
6. 수락 전 배송 요청에는 고객 연락처·상세주소를 공개하지 않는다. 배정 라이더가 픽업하고, 고객의 4자리 인계번호로 완료한다. 실패 5회 시 운영자가 사유를 기록해 한도를 초기화해야 한다. 배송 완료는 결제 완료를 의미하지 않는다.
7. 접수 대기 주문은 15분 만료, 5분 주기 정리 작업에서 취소·재고 복구한다. 만료 후 판매자 접수도 차단한다. 주문·판매자 화면은 입력 중이 아닐 때 15초 간격으로 갱신한다.

외부 배달대행 API, 라이더 GPS 지도, 카드 PG 및 자동 결제·정산은 연결하지 않았다. 자체 라이더 계정과 현장결제 흐름이다. PG 승인이나 외부 라이더 호출을 성공으로 표시하지 않는다.

## 운영 설정

Netlify `@netlify/database` 및 `netlify/database/migrations/`를 통해 별도 Postgres 테이블을 구성한다. 기존 공사·층별·문서 업로드 저장소와 권한을 재사용하지 않는다. 적용된 SQL 마이그레이션은 수정하지 말고 후속 파일을 추가한다.

Netlify Production / Functions 환경변수:

| 키 | 용도 |
| --- | --- |
| `ARIRANG_MARKET_OPERATOR_PASSWORD` | 마켓 운영자 전용 비밀번호, 12자 이상. 아이디 입력 없이 운영자 유형 선택 후 접속. 변경 후 재배포하면 기존 운영자 세션도 만료 |
| `KAKAO_REST_API_KEY` | 서버 전용 위치·주소 조회 REST 키. 브라우저에 노출하지 않음 |
| `ARIRANG_MARKET_PRIVACY_URL` | 실제 운영자의 개인정보 처리 안내 HTTPS 주소 |
| `ARIRANG_MARKET_LIVE_ORDERS` | 실운영 업체·상품·라이더·안내 준비 후 `true`로 설정하여 현장결제 주문 접수 활성화 |

주문 활성화 조건 세 가지(활성화 값, Kakao 키, 개인정보 안내 URL)가 모두 필요하다. 키 값이 존재하는지만으로 주소 API 성공을 단정하지 않으며 각 주문 전 실제 주소 응답을 검증한다. 설정 변경은 재배포해야 반영된다. 고객 정보가 포함된 운영 DB를 임의로 공개 프리뷰/테스트 데이터로 복사하지 않는다.

운영자: 운영 관리 → 지역 → 업체 등록 및 승인 → 상품 → 판매자·라이더 계정 발급. 발급 비밀번호는 한 번만 표시하며 계정 비활성화·비밀번호 재발급 시 해당 세션을 폐기한다. 각 판매자·라이더 계정은 아이디/발급 비밀번호로 접속한다. 운영자 비밀번호 외 기존 층별/문서 관리자 키는 마켓에 사용할 수 없다.

## 검증

- `npm run typecheck`
- `npm run build`
- `npm run test:netlify` (기존 관리자·문서·공개 자료 회귀)
- `npm run test:market` (PGlite/Postgres SQL 트랜잭션·역할·재고·주소·배차·인계·HTTP 경계)
- `node --test tests/market/browser.test.mjs` (실행 가능한 Chromium이 있는 환경, 로컬 HTTPS·합성 데이터·모의 주소 응답)

테스트는 실제 Kakao 키, 고객 주문, 외부 결제, 외부 배달 호출을 사용하지 않는다. 로컬 단일 DB 테스트는 운영 부하 시험이 아니다.

## 탐색 화면 개편 (2026-11-01)

`arirang-market.html`과 `arirang-local.html`은 동일한 지역 장보기 화면을 제공한다. 별도 홍보 안내 화면을 거치지 않는다. 전문관(대분류) → 중분류 → 소분류 → 지역별 공개 상품으로 탐색하며, 분류 정의는 `public/market-taxonomy.mjs`를 서버/브라우저가 함께 사용한다. 소분류는 신규 migration의 `market_products.subcategory`에 저장한다. 기존 중분류 ID는 유지하고 기존 상품의 소분류를 추정해 채우지 않는다.

검색/분류 시 전문관 소개를 숨기고, 검색어·분류·정렬·직접 선택 지역은 URL에 남긴다. 상세 창을 닫으면 목록 조건을 유지한다. 모바일은 상단 고정 검색과 하단 홈/카테고리/장바구니/내 주문을 사용한다. 상품명/제목 MaruBuri, 설명/가격/버튼 Pretendard를 사용하며 CDN 실패 시 시스템 글꼴로 대체한다.

고객 결제 화면은 사용자 지시에 따라 카드결제·외부 배달대행 연결 준비 상태만 안내한다. 현장결제 입력 폼은 표시하지 않는다. 외부 PG/배달 업체가 정해지지 않아 결제·배달 연동 완료로 표시하지 않는다. 기존 주문의 관리 API는 보존한다.

`npm run test:market`에는 DB 분류 저장/지역 카탈로그 및 JSDOM 인터랙션 검사도 포함된다. 이는 실제 Chromium 렌더링 검증과 구분한다. 브라우저 렌더링 검사는 `node tests/online-market-browser.cjs`에서 별도로 실행한다.

## 회원·배송지와 가독성 (2026-11-01)

회원 인증은 기존 `@netlify/identity`를 사용한다. 공개 가입자는 관리자 역할을 받지 않으며 기존 층별·자료 업로드 비밀번호를 회원 권한에 사용하지 않는다. 회원은 `member:<verified Identity UUID>`로 주문 고객과 연결되고, 서버에서 검증한 인증 사용자만 주소록에 접근한다. 주소를 보관하기 위한 별도 장기 인증 쿠키나 자체 비밀번호 DB는 만들지 않는다.

마이페이지: `/arirang-market.html#member`, 배송지: `#addresses`. 로그인/회원가입/인증메일 확인/비밀번호 재설정과 로그아웃을 지원한다. 기본 인증 메일이 건물 홈으로 돌아오는 경우 이메일 확인 완료 및 일반 회원 비밀번호 복구를 마켓 화면으로 안내한다. 기존 관리자 초대 및 관리자 복구 흐름은 유지한다.

배송지는 이름·받는 분·휴대전화·주소·상세주소·배송 요청을 저장하고 최대 10개를 지원한다. 첫 배송지가 기본으로 지정되며, 기본 변경·배송지 선택·수정·삭제가 가능하다. 수정은 버전 검사, 기본 변경/추가는 고객 행 잠금, 조회·변경·삭제는 회원 소유권 검사로 처리한다. 주소·연락처·배송 요청은 localStorage에 저장하지 않는다. 기존 주문의 주소 스냅샷은 주소록 수정/삭제로 바뀌지 않는다.

서버 Kakao 키가 연결되면 저장 시 주소를 확인하고 실제 행정구역에 맞는 운영 배송지역을 연결한다. 키가 없으면 `주소 확인 대기`로만 저장하고 배송 가능 또는 주소 확인 완료로 표시하지 않는다. 키 연결 후 같은 미확인 주소를 다시 저장하면 재검증한다. 서비스 구역 밖의 주소도 주소록에는 보관할 수 있지만 배송 가능으로 표시하지 않는다. 회원 배송지 선택 시 해당 검증된 지역의 상품을 연결한다. 카드결제·외부 배달대행은 별도 준비 상태다.

배포 전 확인한 공개 Identity 설정은 `disable_signup: true`, `autoconfirm: false`였다. 따라서 일반 가입은 아직 열리지 않았다. 운영자가 Netlify Identity의 Registration preferences에서 Open으로 바꿔야 공개 회원가입을 사용할 수 있다. Identity 설정은 대시보드에서만 변경하며 코드가 이를 우회하지 않는다. 실제 사용자 가입/메일 발송은 이번 자동 테스트에서 실행하지 않는다.

건물 홈은 `#online-market` 안내를 층별 작업 영역 앞으로 이동하고 상단 메뉴와 진입 버튼을 강조한다. 모든 공개 HTML에 `readability.css`를 연결하여 화면용 기본 글씨·보조 문구·입력 크기와 대비를 보완한다. 인쇄용 문서의 페이지 나눔에는 공통 화면 규칙을 적용하지 않는다.
